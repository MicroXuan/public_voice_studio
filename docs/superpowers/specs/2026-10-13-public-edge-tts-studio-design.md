# 小宣 Voice Studio 公开版设计规格

## 目标

在新仓库 `MicroXuan/public_voice_studio` 中构建并公开部署一个中文优先的文本转语音网站。首版免费、无需登录，使用 `edge-tts` 当前提供的全部在线语音，不包含任何 Azure Speech 代码、密钥或配置。产品为后续登录、付费套餐和持久额度预留清晰边界，但首版不实现商业功能。

## 产品定位与约束

- 品牌名称为“小宣 Voice Studio”。
- 任何用户都可以通过正式网站在电脑或手机上使用。
- 首版是免费、非商业、实验性公共工具。
- 页面必须说明 `edge-tts` 是调用 Microsoft Edge 在线语音服务的非官方客户端，服务可用性和限额不由本站保证。
- 参考项目 `/Users/xiaoxuan/.codex/worktrees/voice-studio/microsoft_tts` 只作为交互和代码结构基线；不得修改其仓库或 `voice-studio` 分支。
- 新项目只提交到 `https://github.com/MicroXuan/public_voice_studio.git`。

## 部署架构

前后端分离部署：

- 静态前端部署到 Cloudflare Pages，并绑定用户的自有主域名。
- FastAPI 后端部署到 Render Free，使用 Render 域名或 `api.<用户域名>`。
- 前端始终可访问；Render 休眠只影响首次语音生成。
- 前端检测后端冷启动，显示“正在唤醒语音服务”，使用有上限的退避重试恢复请求。
- 正式前端域名和本地开发地址列入 CORS 允许列表。该限制只约束浏览器跨域访问，不限制用户设备、所在地或网络。
- 后端提供健康检查端点，Render 使用单进程运行，以确保内存任务状态一致。

Render Free 的文件系统和进程内状态均视为临时数据。部署不得依赖永久磁盘、数据库或对象存储；服务重启后未完成任务可以丢失，前端必须将其解释为可重试的服务重启。

## 后端组件

### 语音目录

后端通过 `edge_tts.list_voices()` 获取当前可用语音，规范化为稳定的 API 模型并缓存。每个语音至少返回短名称、显示名称、本地化名称、语言地区、性别和状态。目录获取失败时保留最后一次成功缓存；首次获取失败则返回明确的可重试错误。

不得硬编码只有少数中文声音，也不得包含 Azure provider 分支。所有展示和合成均使用 edge-tts 的 voice short name。

### 合成任务

用户提交文本、语音、语速、音调和音量后创建异步任务。任务状态包括排队、执行、完成、失败和过期。前端轮询任务状态，完成后通过同源或允许跨域的音频端点试听和下载 MP3。

音频写入临时目录，采用部分文件加原子重命名，避免返回残缺文件。任务或服务异常时删除部分文件。完成音频与任务记录保留一小时，之后自动清理。

### 公开访问保护

- 单次文本上限：10,000 个 Unicode 字符；纯空白输入拒绝。
- 每个客户端 IP：每小时最多 10 个创建请求。
- 每个客户端 IP：每个 UTC 自然日最多合成 30,000 个字符。
- 每个客户端 IP：同时最多 1 个未完成任务。
- 全站同时最多执行 2 个合成任务；其余请求进入有界队列。
- 队列满时返回可重试的服务繁忙响应，不无限积压。
- 客户端 IP 只从受信任的 Render 代理头解析，不能盲目信任任意转发头。
- 限流和额度首版保存在进程内，服务重启后重置。接口边界应允许未来替换为 Redis 或数据库实现。
- 生成入口预留 Cloudflare Turnstile 验证适配器；首版若部署时能够配置站点密钥则启用，否则以 IP、字符和并发限制作为最低保护。
- API 请求体大小、字段范围和 Content-Type 必须在进入任务队列前验证。

## 前端体验

### 页面结构

- 顶部使用“小宣 Voice Studio”品牌和在线服务状态。
- 主工作区在桌面端采用文本编辑区与声音控制区双栏布局；移动端按文本、声音、参数、生成按钮顺序改为单栏。
- 文本区显示实时字数、上限和清空操作。
- 声音选择器支持关键词搜索，以及语言、地区和性别筛选。
- 常用声音使用浏览器 `localStorage` 收藏，不上传用户偏好。
- 参数包含语速、音调和音量，均有可见标签、数值输出与恢复默认值操作。
- 输出区显示冷启动、排队、生成进度、完成、限流、过期和失败状态。
- 完成后可在页面内试听并下载 MP3。

### 视觉系统

以用户提供的参考界面为布局与质感基线，并将其收敛为更简约、高级的工作台风格：

- 页面使用浅雾灰到极淡薰衣草色背景，中央放置大尺寸白色工作台；内容宽度克制，不铺满超宽屏。
- 桌面端保留左侧高密度语音目录、右侧宽阔文本编辑与参数区的结构，减少参考图中过多的描边、标签和按钮层级。
- 主色采用深靛蓝，主要行动按钮使用克制的蓝紫渐变；成功状态使用低饱和翡翠绿，错误状态使用明确但不过度刺眼的红色。
- 标题、正文与界面统一使用现代无衬线字体，通过字重、字号、间距和数字样式建立层级；中文必须提供系统字体回退，避免缺字。
- 卡片使用细边框、较大圆角、轻微层次和柔和长阴影，不使用厚重玻璃拟态或低对比度拟物化效果。
- 语音条目采用紧凑双列卡片，选中态只使用边框、底色和细微内阴影，不造成布局位移。
- 每个区域只保留一个视觉主操作；辅助操作使用文字按钮或低强调按钮，避免工具条喧宾夺主。
- 所有结构图标使用统一风格的 SVG，不使用 Emoji 代替图标。
- 正文字号不低于 16px，常规文本对比度至少 4.5:1。
- 所有交互目标至少 44×44px，键盘焦点清晰可见。
- 动效保持在 150–300ms，并尊重 `prefers-reduced-motion`。
- 在 375、768、1024 和 1440px 宽度验证，不产生横向滚动。

## 错误处理

面向用户的错误信息不得泄露堆栈、内部路径或代理细节。错误至少区分：

- 后端正在冷启动或暂时不可达；
- 请求频率或每日字符额度已超限；
- 全站队列已满；
- 输入、语音或参数无效；
- edge-tts 上游不可用或没有返回音频；
- 任务因服务重启而丢失；
- 音频已经过期。

所有可恢复错误提供明确的下一步和重试按钮。前端重试不得重复创建已经成功提交的任务。

## 隐私与内容处理

- 不建立账号，不收集姓名、邮箱或支付信息。
- 不保存用户输入文本到持久存储，不把完整文本写入应用日志。
- 仅为限流处理客户端 IP；首版只保留进程内的哈希或最少必要信息。
- 音频为临时文件，并在一小时后删除。
- 页面提供简短的隐私说明、服务限制和滥用禁止说明。

## 测试与验收

自动化测试覆盖：

- 动态语音目录的规范化、缓存和失败回退；
- 文本与参数验证；
- 每小时请求限制、每日字符额度和并发限制；
- 队列满、服务重启、任务过期和音频过期；
- edge-tts 音频流写入、空音频和网络异常；
- CORS 配置和安全响应头；
- 前端 DOM 合约、状态文案和无障碍语义。

发布前运行完整测试、Python 编译检查、容器构建和本地浏览器验证。浏览器验证覆盖桌面与 375px 移动端、键盘操作、减少动画、冷启动提示、语音搜索筛选、生成、试听和下载流程。

## 交付与上线

- 提交完整源码、测试、Dockerfile、Render 配置、Cloudflare Pages 配置、环境变量示例和部署文档。
- GitHub `main` 分支作为部署源。
- 后端先部署到 Render Free 并完成健康检查与真实 edge-tts 冒烟测试。
- 前端部署到 Cloudflare Pages，再配置正式 API 地址和自有域名。
- 上线后验证首页、语音目录、真实合成、试听、下载、限流和移动端布局。

## 后续商业化边界

首版不实现账号、支付、订阅、持久任务或商业 SLA。未来扩展时：

- 将限流存储接口替换为 Redis 或数据库；
- 增加账号、套餐和按字符计量；
- 将临时音频迁移到对象存储；
- 将队列迁移到持久任务系统；
- 在商业使用前重新确认所用 TTS 服务的授权、条款与可靠性，并根据需要迁移到正式商业 TTS API。

域名名称、DNS 服务商和 Turnstile 密钥属于部署阶段输入，不影响本设计的代码结构。
